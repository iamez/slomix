# Timing Data Sources Reference

This document clarifies the different sources of timing data in the Slomix system.

> **Rewritten 2026-08-18** after the round-duration RCA: the previous revision
> described a JSON stats format (`oksii-game-stats-web.lua`) that production
> never used, was three webhook versions behind, and recommended treating the
> `actual_time` vs `actual_duration_seconds` divergence as a surrender-detection
> *feature* — which let a 15% duration inflation go unnoticed for months.

---

## Overview: Three Sources of Timing Data

| Source | Script | Where Stored | Purpose |
|--------|--------|--------------|---------|
| **Stats file header** | `vps_scripts/c0rnp0rn8.lua` (text, backslash-separated) | `rounds` table | Round metadata + per-player TAB stats |
| **Slomix Webhook** | `vps_scripts/stats_discord_webhook.lua` v1.7.x | `lua_round_teams` table, mirrored into `rounds.actual_duration_seconds` | **Measured** round timing (the source of truth) |
| **Filename** | Generated by server | `rounds.round_time` | File creation time of day (`HHMMSS`) — **not a duration** |

**Single source of truth for "how long did this round last":**
`shared/round_time.py` → `round_duration_seconds()` (Python) /
`round_duration_sql()` (SQL). Both mean
`COALESCE(NULLIF(actual_duration_seconds,0), parse_mmss(actual_time))`.
Verified against 213 demo-recorded matches (2026-05-15 → 2026-08-17):
**100% within ±2 s.** Never read `rounds.actual_time` directly as a duration.

## Stats File Header (c0rnp0rn8.lua) — the real contract

Production stats files are plain text. Line 1 is a backslash-separated header
(`vps_scripts/c0rnp0rn8.lua:438`):

```
server\map\config\file_round\defender\winner\TIMELIMIT\NEXTTIMELIMIT\PLAYTIME_MS
  f1     f2    f3      f4       f5       f6      f7         f8           f9
```

| Field | DB column | Unit | What it actually is |
|-------|-----------|------|---------------------|
| f7 `TIMELIMIT` | `rounds.time_limit` | `M:SS` text | `timelimit` cvar. In R2 this is the time R1 set. ⚠ `'0'` in most modern rounds — use `lua_round_teams.time_limit_minutes` instead. |
| f8 `NEXTTIMELIMIT` | `rounds.actual_time` | `M:SS` text | **`g_nextTimeLimit` cvar = the stopwatch TARGET for the next round — NOT a measured duration.** When attackers complete, it happens to equal their time. On surrender the game never sets it, and the Lua fallback (`c0rnp0rn8.lua:433-435`) writes the **full timelimit** / R1's time. |
| f9 `PLAYTIME_MS` | (parser input only) | **milliseconds** | `roundEnd - roundStart - pauses` via `trap_Milliseconds`. Can be **negative** on the `et_ShutdownGame` save path (roundEnd never set). Parser normalizes via `normalize_header_playtime()` (`bot/community_stats_parser.py`). |

**RCA 2026-08-18 (docs/research/SUPERBOYY_BAZA_RECONCILE_2026-08-18.md +
plan `quizzical-splashing-stearns`):** in the last 3 months, 67/448 valid
rounds (15.0%) had `actual_time` inflated by up to +362 s. All 67 were
`round_outcome='Fullhold'` with `lua_round_teams.surrender_team > 0`;
0/370 non-surrender rounds diverged. The daily data-plausibility audit rule
`rounds_actual_time_diverges_without_surrender` now alerts if the two sources
ever disagree outside that surrender case.

**Per-player time:** `player_comprehensive_stats.time_played_seconds` comes
from Lua TAB[22] (healthy); when TAB[22] is absent the parser falls back to
f9 (ms → s). `time_dead_minutes` comes from TAB[26] — independent.

## Spawn Tracking (v1.6.0+)

**Script:** `stats_discord_webhook.lua` (Slomix custom)

**Purpose:** Independent dead-time validation using death→spawn intervals.

**What is captured (per player, per round):**
- `spawn_count`, `death_count`
- `dead_seconds` (sum of death→spawn gaps, plus end-of-round tail if still dead)
- `avg_respawn_seconds`, `max_respawn_seconds`

**Storage:** `gametime-*.json` (`meta.spawn_stats`) → `lua_spawn_stats` table.

This does **not** replace `time_dead_minutes` from stats files; it is a second
source to validate or identify mismatches.

## Slomix Webhook Timing (stats_discord_webhook.lua)

**Script:** `stats_discord_webhook.lua` v1.7.2 (our custom script)

**Purpose:** Measures timing by hooking gamestate transitions directly —
independent of the stats file header.

- `actual_duration = round_end_unix - round_start_unix - total_pause_seconds`
- Sanity cap at timelimit with warmup correction (v1.6.2)
- `end_reason` = `objective` / `surrender` / `time_expired`; surrender votes
  tracked (`surrender_team`)

**Database Storage (`lua_round_teams` table):**
| Column | Type | Description |
|--------|------|-------------|
| `round_start_unix` / `round_end_unix` | BIGINT | GS_PLAYING start / GS_INTERMISSION start |
| `actual_duration_seconds` | INTEGER | Playtime excluding pauses — **the measured truth** |
| `total_pause_seconds`, `pause_count`, `lua_pause_events` | | Pause tracking |
| `lua_warmup_seconds`, `lua_warmup_start_unix` | | Warmup tracking (v1.2.0+) |
| `end_reason`, `surrender_team` | | How the round ended |
| `time_limit_minutes` | | Effective timelimit (use this, not `rounds.time_limit`) |

The bot mirrors `actual_duration_seconds`, `total_pause_seconds`,
`pause_count`, `end_reason`, `round_start_unix`, `round_end_unix` and
`winner_team` onto `rounds` (`bot/ultimate_bot.py`, webhook handler).
⚠ It deliberately does **not** rewrite `rounds.actual_time` — that stays the
raw header value (stopwatch clock), which is why consumers must go through
`shared/round_time.py`.

## Computed Timing (Bot-Side Aggregation)

```
Intermission (R1→R2) = R2.lua_warmup_start_unix - R1.round_end_unix

Map Totals:
  Total playtime  = R1.actual_duration_seconds + R2.actual_duration_seconds
  Total warmup    = R1.lua_warmup_seconds + R2.lua_warmup_seconds
  Total pauses    = R1.total_pause_seconds + R2.total_pause_seconds
  Wall-clock time = R2.round_end_unix - R1.lua_warmup_start_unix

Session Totals: Sum across all rounds in gaming_session_id
```

## Which Source to Use?

| Use Case | Recommended Source |
|----------|-------------------|
| Round duration (any purpose) | `shared/round_time.py` helpers (`round_duration_seconds` / `round_duration_sql`) |
| Per-player playtime | `player_comprehensive_stats.time_played_seconds` |
| Effective timelimit | `lua_round_teams.time_limit_minutes` (`rounds.time_limit` is `'0'` in modern rounds) |
| Attackers completed? (map winner) | `winner_team != defender_team`; surrender via `lua_round_teams.surrender_team` / `end_reason` — **never** a clock comparison |
| Stopwatch clock display (time an attack set) | `rounds.actual_time` (the only legitimate direct use) |
| Pause / warmup / intermission | `lua_round_teams` columns, computed as above |
| Surrender detection | `lua_round_teams.end_reason` / `surrender_team` (the old advice — diffing `actual_time` vs `actual_duration_seconds` — is now an ALERTING invariant, not a feature) |
