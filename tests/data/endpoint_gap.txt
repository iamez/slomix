# H1 endpoint ratchet (docs/design/09 §H1) — paths the legacy frontend calls
# (plus endpoint_required_extra.txt) that the NEW frontend does not cover yet.
# Every build phase deletes lines; the goal is an EMPTY file by switchover.
# Before deleting a line: verify against live /openapi.json AND call it once
# (docs/design/07 §C.1). Seeded 2026-08-24 from the extractors themselves.
#
# 2026-08-29: 64 -> 120. Not a regression — a correction. The extractor read
# all of website/frontend/src, so the OLDER React tree (src/pages) counted as
# migration progress and 56 paths it alone calls looked covered. The scan
# root is src/app now; these 56 were always missing.
#
# 2026-08-30, /api/stats/sessions: this line will NOT close by the new app
# adopting the path. Owner's decision that day was that /api/sessions is the
# source for session listings, and it now carries everything its sibling had
# (duration_seconds, start_time, end_time, player_names, total_deaths, search)
# with both endpoints agreeing on all of them. The line stays because the
# ratchet measures what legacy calls and the new app does not, which is still
# true and should stay visible; it closes when legacy sessions.js/sessions2.js
# are retired, not before. Do not delete it to make the number smaller — the
# test recomputes the set and would fail anyway, which is the ratchet working.
#
# 2026-09-02, /api/bets and /api/bets/market: availability slice 2 built the
# BETTOR surface (wallet, pools, my bet, the stake POST on
# /api/bets/market/{market_id}/bet). Neither line closed by that:
# /api/bets is legacy bets.js's `${API_BASE}/bets` base string — no such
# endpoint exists (docs/design/07 §C.1 calls it an abbreviation), so it goes
# when bets.js retires; /api/bets/market is the ADMIN market-open POST, which
# the owner kept out of slice 2 (open/settle stayed in legacy availability.js).
# The templated bet call must NOT clear it — test_templated_write_does_not_
# register_its_truncated_prefix pins that.
#
# 2026-09-05, /api/bets/market DELETED: slice 3 built the admin half —
# postOpenMarket() posts the bare path, so the extractor sees it without the
# truncation hazard above. Verified per docs/design/07 §C.1 before deleting:
# the path is in the LIVE /openapi.json as a POST, and one call was made — an
# anonymous POST answers 401 "Not authenticated" (so does the settle sibling).
# A write endpoint is verified by the call it REFUSES; calling it for real
# would have opened a market in the dev database to prove a route exists.
# /api/bets stays: bets.js still holds the base string.
#
# 2026-09-05: 3 -> 19. Not a regression — a correction, and the second one of
# this kind (see the 64 -> 120 note above). The legacy extractor stopped at the
# first `${`, so `wrapped.js`'s `${API_BASE}/players/${guid}/wrapped` was read
# as the prefix `/api/players`. A truncated prefix counts as covered the moment
# the new app calls anything deeper, and it does call
# `/api/players/{identifier}/profile` — so a DIFFERENT, unbuilt operation
# counted as migrated. Measured: 29 legacy calls carry an interpolation with a
# segment behind it and 16 of them were invisible this way.
#
# The extractor now reads THROUGH interpolations and writes each as `{}`, so a
# call is required as a shape (`/api/players/{}/wrapped`) that only a real call
# to that shape can clear. Every one of the 16 was verified twice: it resolves
# to a live path in docs/api/openapi.json, and `src/app` contains no call to it
# (the two `graphs` hits in the app are prose in comments).
#
# ⚠️ These 16 are NOT phase-7 scope by themselves. Some belong to pages already

# thinner than the ratchet claimed — that is the finding, and it is the owner's
# call what to do about it.
