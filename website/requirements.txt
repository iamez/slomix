# Explicit starlette pin (matches the root manifest and both prod venvs) so CI
# audits a deterministic version rather than whatever the resolver floats to.
#
# This is now the 1.x line. It was held at 0.52.1 because
# prometheus-fastapi-instrumentator 7.x constrained starlette<1.0, which made
# the 0.x advisories a time-boxed accepted debt. Instrumentator 8.x requires
# starlette>=1.0 instead, and FastAPI 0.133.1 asks only for starlette>=0.40.0
# with no upper bound — so bumping the two together resolves cleanly and the
# debt is paid rather than re-deferred. The matching pip-audit ignores in
# .github/workflows/tests.yml are removed in the same change.
starlette==1.3.1

# ── Formerly: transitively required by the bot service layer ────────────────
# discord.py and matplotlib were pinned here because the web service imported
# them at startup — not as real dependencies, but through package __init__ side
# effects: importing any submodule of bot.services or bot.core ran the parent
# __init__, which eagerly imported every sibling, two of which pull discord and
# matplotlib.
#
# #603 made both packages re-export lazily (PEP 562), so the chains are gone.
# Measured on the real app: 1316 modules and 1.90s at startup before, 829 and
# 1.32s after, with neither package present. tests/integration/
# test_web_does_not_import_bot_discord.py keeps it that way — nothing else would
# fail if an eager import came back, the venv would just quietly need them again.
#
# cryptography and aiosqlite stay: they are genuinely the web service's own,
# reached through the redis client (redis/utils.py) and
# website/backend/local_database_adapter.py's SQLite dev fallback respectively.
